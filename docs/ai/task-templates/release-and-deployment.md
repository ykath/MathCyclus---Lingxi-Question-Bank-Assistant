# 发布与部署任务合同

## 输入

- 当前源码分支和明确的发布范围。
- `env.example`、依赖文件、迁移文件、启动脚本和发布白名单。
- 需要保留的用户私有数据迁移或恢复方案。

## 预期输出

- 不含 API Key、个人路径、数据库、PDF、题图、报告和运行日志的源码发布包。
- 可执行的安装、初始化、迁移、启动和恢复说明。
- 发布包 manifest、依赖检查结果和 smoke 结果。

## 必须遵守

- 发布内容使用白名单检查，不靠手工猜测哪些文件应该上传。
- 用户私有数据和程序源码分离；数据库迁移通过正式 `db/migrations/` 文件完成。
- 可选依赖（例如 OpenCV）不能成为基础安装的隐性必需项。
- 记录当前版本、迁移版本、已知限制和回滚方式。

## 禁止事项

- 不提交 `.env`、API Key、个人绝对路径、真实题库、报告和日志。
- 不用 Git reset、checkout 或覆盖操作清理用户已有改动。
- 不在没有备份和兼容检查的情况下自动覆盖用户数据库。
- 不把测试生成物和本地任务目录混入发布包。

## 验收检查

- 发布包 smoke 通过，私有文件排除检查通过。
- 新环境能够按文档初始化、迁移和启动。
- 迁移前后 schema 版本明确，旧数据恢复路径可用。
- 启动器、可选依赖、Local API 文档和主程序入口一致。
- 明确列出本次未验证的外部环境，例如 API 配额、MinerU 云端凭据或 LaTeX 工具链。
