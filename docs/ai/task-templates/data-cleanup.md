# 数据清洗任务合同

## 输入

- 明确范围的 SQLite、旧 TeX、试卷来源、题目关系或资源审计结果。
- 已确认的人工决策，例如保留、删除、拆分、改名、合并关系或暂缓处理。
- 备份目标、dry-run 参数和本次任务标识。

## 预期输出

- 只读候选报告和可审阅的差异摘要。
- 人工确认后生成备份、变更清单、审计结果和可回滚信息。
- SQLite、旧 TeX、来源关系、图片资源和索引保持一致，或明确记录暂时差异。

## 必须遵守

- 顺序固定为：备份 → dry-run → 人工确认 → 写入 → 写后审计。
- 来源位置冲突、完全相同、高度相似和变式关系分别处理。
- 只对明确确认的题目和字段执行变更；不因相似度自动删除题目。
- 每次删除、合并、拆分或迁移都保存 manifest 和操作原因。

## 禁止事项

- 不直接在正式数据库上试跑未经审阅的脚本。
- 不用“修复 warning”的方式删除数据或覆盖来源信息。
- 不把历史日志当作当前字段规则。
- 不删除无法确认用途的备份、脚本或本地数据。

## 验收检查

- dry-run 与实际写入的目标范围一致。
- 写入前后都有数据库审计，且没有新增 blocker。
- 题目数量、来源关系、资源引用和旧 TeX 桥接状态符合预期。
- manifest 能说明变更对象、前后值、备份位置和人工决策。
- 运行数据清洗、关系、资源和 SQLite/旧 TeX 桥接相关检查。
