# PDF / 图片识别任务合同

## 输入

- 用户明确提供的 PDF、图片或页面范围。
- 可选的年份、来源类型、卷别代码、试卷名称和题号范围。
- 当前有效的 OCR/TeX 提示词版本，以及可用的 MinerU 或 PyMuPDF 能力。

## 预期输出

- 私有任务目录中的 `job_manifest.json`、`draft_payload.json` 和必要的页面图或裁剪图。
- 每道题的草稿状态、来源候选、题干 TeX、选项、答案、解析、图片资源和错误信息。
- 任务摘要和逐题草稿中的 provenance，包括输入文件哈希、解析器、模型、提示词指纹和识别器版本。
- 可恢复的进度、暂停状态、失败项和重试记录。
- 人工审核后，才允许进入正式题库和修订记录。

## 必须遵守

- 优先使用云端 MinerU 进行版面解析；不可用时使用 PyMuPDF 回退。
- 按页或题目候选调用 AI，不反复发送整份 PDF。
- 图片只绑定实际存在的非 TikZ 题内资源；已有 TikZ 保留源码。
- 没识别到来源时使用“未标记来源”，不伪造年份或试卷名称。
- 缺答案或解析不作为识别失败；缺题干、页面错位和资源无法解析必须标记复核。

## 禁止事项

- 不直接写入正式 `question`、`paper` 或关系表。
- 不因为模型输出看起来完整就跳过人工二次审核。
- 不覆盖已经成功的草稿项来实现重试；重试必须保留原错误和新的尝试记录。
- 不把 PDF、页面图片、任务报告或 API 配置加入 GitHub 发布包。

## 验收检查

- 任务可列出、加载、暂停、恢复和重试。
- 页面数、题目数、成功数、失败数和待审核数一致。
- 题号、跨页合并、图片绑定、`problem` / `choices` / `answer` / `solutions` 结构通过检查。
- 任务目录不写正式数据库；正式入库只能从人工审核入口触发。
- 至少运行 PDF 导入、AI 队列、图片资源和草稿审核相关 smoke。
