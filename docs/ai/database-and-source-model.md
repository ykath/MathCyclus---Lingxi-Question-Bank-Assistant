# 数据库、来源与关系模型

## 1. 核心对象

- `question`：题目本体和结构化字段。
- `paper` / `paper_question`：试卷及题目在试卷中的位置。
- `book` / 教材关系：教材、册次、章节、页码和题目关系。
- `topic` / 专题关系：专题、分组、顺序和题目关系。
- `question_asset`：题目图片和其他资源。
- `question_revision`：正式题目变更历史。
- `question_import_draft`：AI/OCR/PDF 导入草稿。
- `question_equivalence`：同题、相似题和变式题关系。

## 2. 筛选口径

- 年份、卷别代码、试卷来源和题号是不同维度。
- 只选试卷来源而不选年份时，可以跨年份查看同名来源；数据库中的不同年份试卷仍然是不同 `paper` 记录。
- 试卷名称标准化和别名匹配用于减少显示分裂，但不能把不同年份或不同文理赛道错误合并。
- “未标记来源”是合法来源类型，不要用虚假的年份或试卷名填充。

## 3. 重复题口径

1. 来源位置冲突：同一试卷的同一题号/小题位置已存在题目，优先阻止或要求人工确认。
2. 完全相同：归一化后的题干和图片占位数量一致，登记同题候选。
3. 高度相似：统一相似度算法达到主阈值，登记相似题候选。
4. 语义推荐：知识板块、公式或表述相关，但未达到关系阈值，只用于参考，不能自动登记为相似题关系。

任何关系确认都不自动删除题目。合并、保留多份、变式关系和跳过决策应有人工记录。

## 4. 写库与迁移

- schema 变化通过 `db/migrations/`，不要只修改本地数据库。
- 数据清洗按“备份 → dry-run → 人工确认 → 写入 → 审计”执行。
- 运行脚本的读写边界见 `../planning/maintenance_script_catalog.md`。
- 正式数据库、图片和报告都是本地私有数据，不随源码发布。
